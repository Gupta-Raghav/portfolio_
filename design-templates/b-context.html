Large tool output handling

Anything over the threshold goes to a session file. The model gets the first and last 500 characters plus a path it can grep. The full output stays on disk for replay. I shipped it behind a flag, watched the numbers, then made it the default.

tool   execute_bash   87,432 chars
write  session/tool-outputs/bash-a1b2.txt
model  head 500  ...  tail 500
result ~1k chars in context
02 / context

Summarization that keeps the cache warm

The agent estimates usage after pending tool results, before the next call. Crossing the line triggers a task-oriented summary that reuses the cached prompt prefix, so compaction is close to the cost of one turn. The cold, expensive path is only a fallback.

< 80%     proceed
80 to 95% summarize  cache reused
> 95%     truncate   fallback only
03 / safety

Checkpoints you can trust

A snapshot before every write, deduplicated by content hash. Revert restores each file to its first pre-change state, including multi-file renames, sub-agent edits, and files the agent created or deleted. History is append-only, so an undo is a new record.

write  src/parser.ts   snapshot a1b2
write  src/parser.ts   dedup, same hash
rename 4 files        per-file snapshots
revert restored 5 files
