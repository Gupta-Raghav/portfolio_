01 / impact

What changed for people using Kiro.

I own what the agent keeps, what it lets go, and how it undoes. Each piece ships once, in the runtime, and reaches every client.

01

Long sessions keep going.

Hitting the context limit used to end the conversation. Now the agent summarizes and carries on, and because the summary reuses the prompt cache it costs about as much as a normal turn. That is what lets people hand Kiro multi-hour tasks.

Keep the task in view, not the log.

Big outputs filled the window, forced early and expensive summarization, and disturbed the prompt cache so every later turn cost more. I designed a layer that catches oversized results before they reach the model, moves them aside, and leaves a short preview with a pointer the agent can follow.

The tradeoff is that the model sees less by default. The preview usually shows the error and the summary line, which is enough to choose the next step, and the full output is always one search away. I shipped it as an experiment, proved it out, and turned it on for everyone.

04 / case studies

More from the runtime.

checkpoints

Undo for an agent that edits many files

A bad multi-file edit five turns ago had no clean undo, sub-agents edited files the parent never saw, and any client could ask for the revert. I drove the experience with UX and Product, took the design through review, and shipped it. Every edit is reversible from any message, in any client.

summarization

Sessions that outlive the context window

At the limit, the conversation was simply lost, and the old compaction broke the prompt cache. I designed around the cache: a primary path that reuses what the model already has, and a fallback that always succeeds when the window is nearly full. Then I brought it into the unified runtime. Sessions carry on by themselves, at about the cost of one turn.
